# Measure P04 message performance

The `collaboration-message-performance` workflow job compares the squash-merged P03 parent `bea36acff7b55ea4ed0f4a4feccde6b638eea4db` with the selected P04 branch head on a GitHub-hosted Linux runner. The candidate must descend from `e52ab08e3efd31eb74e405bb745350fa463d7da1`. Only this harness and the performance workflow may change after that commit. Its extension tree matches the reviewed P04 product commit `87ecbd7b60f62282b2565b9f09d633477ba5ca5c`.

The previous P03 baseline `e40b6bbe985c5663ebea7756f175f210402044fd` and the merged baseline have identical extension and product-command trees. Their diff is limited to platform verification scripts and their workflow. It does not change Go files, module or workspace manifests, the PiG source declaration or patch, or devenv inputs. Inspect it with `git diff --name-status e40b6bbe985c5663ebea7756f175f210402044fd bea36acff7b55ea4ed0f4a4feccde6b638eea4db`.

Dispatch `compare-pig-performance.yml` on `feat/collaboration-P04-message-receipts` with `candidate_sha` set to the exact branch head and `p04_release` set to `true`. The default `false` value prevents measurement. The job checks the dispatch SHA and parent, builds each checkout serially inside its declared devenv environment, and runs a paired functional smoke before it releases measurement. It retains control and scenario artifacts even when a step fails. It does not upload build caches.

Each side has its own package identity. The parent uses the PiG source declared by its checkout and host digest `c9cc629ea6dde421e10c18e2e3d04982c389ddb11a25383dd40acb39ae7ccf5e`. The candidate uses its declared source and host digest `e728619e3a6f82e01c41ac16e45233df656487960d5ad64ca2395d56b8051070`. The build checks the declaration, patch, packaged host, Nix source and SDK hashes, and Go workspace module paths. Both products use Go 1.27.4 and the same `-p 2 -mod=readonly -trimpath -buildvcs=false` flags. The control artifact records their commits, trees, binaries, build environments, module lists, source and SDK hashes, and toolchain identities.

The smoke runs one parent pair and eight peer messages across four teammates. The measurement runs five warmups per side, then 20 interleaved parent pairs with alternating order. Each parent fixture sends a steer and a follow-up, verifies their tool results, and checks the native child transcript and provider requests. The peer fixture sends 100 messages in a ring of four teammates. Its independent inspector matches every accepted result, body, receipt, native entry, and provider wake and checks that no lead request occurs during sibling delivery.

All fixture timings use the monotonic clock. Peer acceptance ends at the sender provider request containing the accepted tool result, after the product's durable write. The result includes fixture and RPC overhead, so it is a conservative upper bound. A receipt filename can become visible before directory sync and does not prove durable acceptance. Recipient delivery ends at the first poll that observes the native entry. Idle wake ends at the recipient provider request containing the message. The output retains the last absent and first present poll timestamps, raw requests, native transcripts, bodies, and receipts.

The summary uses nearest-rank p50 and p95. It fails a parent regression only when the candidate p95 exceeds the parent by both 20% and 50 ms. It evaluates the combined samples and each parent message mode. Peer acceptance must be below 100 ms p95, and recipient delivery must be below one second p95. If either conservative bound misses its threshold, the result is inconclusive. Local smoke runs check the fixture and identities but do not establish a performance result.
