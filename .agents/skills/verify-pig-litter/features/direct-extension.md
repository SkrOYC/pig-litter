# Direct extension selection

Explicit `pig -e /ABSOLUTE_PATH/extensions/pig-litter` selects the Go Resource through its `Extension()` factory. It registers the six background controls and `/pig-litter`. The factory and command live in `extensions/pig-litter/adapter.go`.

Startup displays the selected extension and normal editor. `/pig-litter` opens the retained direct-child panel. `/pig-litter help` explains discovery, spawn, inspect, message, stop, and wait. Selection and help make no completion request. The child widget appears when a control initializes ownership. Discovery can draw its initial counts.

## Drive the repository source

Supply an exact model in `PIG_LITTER_MODEL` and run:

```sh
.agents/skills/verify-pig-litter/scripts/live.mjs \
    --model "$PIG_LITTER_MODEL" --case direct
```

The doctor records the resolved command source and Git revision when available. Source-directory loading requires the repository's Go build environment. The helper also requires an available exact model and ready authentication, even though this case makes no completion request. It selects the repository extension by absolute path from owned scratch, captures readiness and the diagnostic, and requires clean exit. It doesn't replace a named Piglet proof.

For isolated terminal behavior, run the pinned wrapper. Its direct case uses the prebuilt repository Go extension and a deterministic loopback provider. It also checks compact and expanded cards, active-first widget rows, retained-child controls, messages, same-UUID resume, live reports, root Escape, reload, root isolation, resize, editor return, scrollback, and cleanup. It records PiG's native exit status but does not prove source-directory loading. Evidence stays under `.pstack/evidence/go-tui/`.
